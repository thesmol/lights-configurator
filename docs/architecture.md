# Архитектура и модель данных

Приложение — TypeScript-прототип конфигуратора. React управляет проектом, Three.js отображает комнату, Node.js предоставляет REST API. Каталог и цены демонстрационные. В обычном запуске итоговую цену определяет сервер. Для GitHub Pages те же функции расчёта выполняются в браузере.

## Товар и установленный элемент

Товар каталога имеет произвольный строковый `id`. Типы `spot`, `wide`, `line` в поле `shape` описывают геометрию представления, а не перечень допустимых артикулов. Десятки моделей могут использовать одну геометрию с разными размерами, характеристиками и ценами. В интерфейсе используется `imageUrl`, если товар имеет изображение; иначе показывается SVG-иллюстрация.

`TrackProduct` содержит тип монтажа, цену секции, длину секции, допустимые формы и правила комплектации. Установленный `TrackPlacement` ссылается на товар через `productId`, но имеет собственный числовой `id`, цвет, положение, форму, размеры и светильники. Несколько треков одного товара не разделяют своё состояние.

При добавлении светильник автоматически попадает на свободный участок выбранного трека. Его можно переместить на плане без отдельного переключателя участков.

Светильник хранит `type` — ID товара, `segmentId` — ID участка своего трека и `t` — положение от 0 до 1 вдоль доступной части участка. Его ID уникален внутри трека. Поэтому выделение светильника хранит пару `{trackId, id}`. Выделение трека хранится отдельно в `selectedTrackId`, независимо от активного трека настроек. В режиме плана Delete и Backspace удаляют выделенный светильник или трек вместе с его приборами; при вводе текста эти клавиши работают как обычно. Клик вне элемента снимает выделение.

## Формы и размеры

Каждая форма задаёт массив параметров и массив прямых участков. Координаты концов участка — коэффициенты параметров `length`, `depth`, `tail`. Геометрический модуль рассчитывает точки и центрирует фигуру относительно положения трека. UI строит поля из описания формы.

| Форма                        | Параметры                                                                |
| ---------------------------- | ------------------------------------------------------------------------ |
| Линия                        | `length` — длина                                                         |
| Угол, П-форма, прямоугольник | `length` — ширина, `depth` — глубина                                     |
| Две линии                    | `length` — длина каждой линии, `depth` — расстояние                      |
| Z-форма                      | `length` — верхний отрезок, `depth` — вертикаль, `tail` — нижний отрезок |
| Т-форма, крест               | `length` — общая ширина, `depth` — общая глубина                         |

`length` в установленном треке означает основной размер формы. **Общая длина** получается только суммированием реальных участков через `trackLength`. Для новых форм из прямых участков можно расширить каталог шаблонов, не добавляя ветвления в JSX и 3D-рендерер. Точки ветвлений должны быть концами отдельных участков.

При смене формы приборы сохраняются: сначала используются прежние участки, затем свободные места новых. Изменение отклоняется целиком, если приборы не помещаются, фигура выходит за комнату или пересекает соседний трек. Перетаскивание прибора выбирает ближайший участок его трека и ближайшее свободное место; между разными треками прибор пока не переносится.

## Состояние и сохранение

Проект имеет `schemaVersion: 2`. Старые проекты с одним `trackL`, `mount` и общим `fixtures` автоматически преобразуются в один линейный трек. Ключ localStorage `lights-prototype-v1` сохранён для совместимости. JSON экспортирует текущее состояние; импорт проверяет размер файла, нормализует числа, идентификаторы и размещение. Файлы с более новой неизвестной версией отклоняются.

При нормализации заведомо некорректного или переполненного импортированного проекта размеры ограничиваются, а не помещающиеся приборы могут быть отброшены. Обычные изменения через интерфейс не удаляют приборы ради уменьшения трека: невалидное изменение отклоняется.

## Большой каталог и производительность

Диалоги каталогов треков и светильников показывают не более шести товаров за страницу. Поиск доступен даже в маленьком каталоге; фильтры показываются при наличии нескольких категорий и переносятся на следующую строку. Каталог светильников остаётся открытым после добавления: можно добавлять несколько приборов подряд, сохраняя поиск, фильтр и страницу. Счётчик показывает число приборов на текущем треке; при нехватке места соответствующие карточки блокируются. Закрытие — кнопкой «Готово», крестиком, Escape или кликом по фону. Поиск по имени и артикулу, категории и страницы в серверном режиме обращаются к REST; в Pages применяется тот же алгоритм локально. Bootstrap `/api/catalog` пока загружает полный снимок метаданных для геометрии, восстановления проекта и фильтров. Это проверено на 123 светильниках и 32 профилях; для значительно больших каталогов следующий шаг — загрузка деталей выбранных товаров по ID и отдельные метаданные фильтров.

Расчёт цены откладывается на 200 мс. Изменение положения, цвета и камеры не вызывает запрос. Старый результат остаётся на экране до ответа; выгрузка спецификации недоступна, пока расчёт не соответствует текущему проекту. Новый запрос отменяет устаревший.

3D кэширует объекты по трекам. Перемещение и изменение размеров обновляют их преобразования. Изменение набора приборов перестраивает только соответствующий трек. Число источников света ограничено четырьмя; остальные приборы сохраняют видимые линзы. Свет иллюстративный, не расчётный. Потолок односторонний: виден снизу и не перекрывает вид сверху.

Текущие защитные пределы: 24 трека, 200 приборов в проекте, комната до 12 × 12 м. Свободное размещение ограничено размерами комнаты, габаритами приборов и зазорами. Это пределы прототипа, а не характеристики продукции.
