# Устройство проекта

React хранит состояние проекта и рисует интерфейс. Three.js отвечает за комнату. Геометрия треков, подбор комплектующих и расчёт цены вынесены в `domain/`: этот код используют и клиент, и сервер.

При обычном запуске клиент получает каталог и цену через API. На GitHub Pages сервера нет, поэтому сборка с `VITE_PAGES_DEMO=true` считает всё в браузере.

## Где искать код

| Задача                                  | Файлы                                                                          |

| Формы треков и геометрия                | `domain/trackLayouts.ts`, `domain/trackGeometry.ts`                            |
| Комплектующие и цена                    | `domain/trackRequirements.ts`, `domain/pricing.ts`                             |
| Поиск и фильтрация                      | `domain/catalogQuery.ts`                                                       |
| HTTP API                                | `server/app.ts`; запуск — `server/index.ts`                                    |
| Состояние, загрузка и изменение проекта | `src/project.ts`, `src/projectActions.ts`                                      |
| Расстановка светильников без наложений  | `src/placement.ts`                                                             |
| Каталоги                                | `src/CatalogPicker.tsx`, `src/CatalogDialog.tsx`, `src/TrackCatalogDialog.tsx` |

`shared.ts` реэкспортирует типы, тестовый каталог и функцию расчёта. В `domain/` нет зависимостей от React, DOM или HTTP.

## Каталог и проект

`TrackProduct` описывает товар: тип монтажа, длину и цену секции, доступные формы и комплектующие. `TrackPlacement` описывает конкретный трек в комнате: ссылается на товар через `productId`, хранит размеры, цвет, координаты и список светильников. У двух треков одного артикула могут быть разные настройки.

У товара строковый ID. Поле `shape` светильника выбирает способ отрисовки: `spot`, `wide` или `line`. Модели с разными артикулами могут использовать одну форму, но иметь разные габариты и характеристики. Для карточки можно передать `imageUrl`; без него показывается SVG.

Светильник в проекте хранит:

- `type` — ID товара;
- `segmentId` — участок трека;
- `t` — положение от 0 до 1 вдоль доступной части участка.

ID светильника уникален только внутри своего трека. Поэтому выбранный светильник записывается как `{trackId, id}`. Для выбранного трека есть `selectedTrackId`, а для трека, настройки которого открыты, — `activeTrackId`.

## Формы треков

Форма состоит из прямых участков. Их координаты вычисляются через `length`, `depth` и `tail`. Поля настройки строятся по описанию формы в `trackLayouts.ts`.

| Форма                        | Размеры                                                                  |
| ---------------------------- | ------------------------------------------------------------------------ |
| Линия                        | `length` — длина                                                         |
| Угол, П-форма, прямоугольник | `length` — ширина, `depth` — глубина                                     |
| Две линии                    | `length` — длина каждой линии, `depth` — расстояние между ними           |
| Z-форма                      | `length` — верхний отрезок, `depth` — вертикаль, `tail` — нижний отрезок |
| Т-форма, крест               | `length` — ширина, `depth` — глубина                                     |

Общую длину считает `trackLength`, суммируя участки. Поле `length` само по себе этой суммы не содержит.

Чтобы добавить форму из прямых участков, нужно описать её параметры и отрезки. В местах соединений отрезки должны заканчиваться: по этим точкам считается комплектация.

Новый трек получает первую известную форму из `layoutIds` товара. Размеры подгоняются под комнату в пределах, разрешённых формой. Если места нет, добавить трек нельзя.

При смене формы светильники остаются на прежних участках, где это возможно, а остальные перемещаются на свободные. Если все не помещаются, изменение отменяется. То же происходит при выходе за стены или пересечении соседнего трека. Повторный клик по текущей форме ничего не меняет.

## Размещение и выбор

Новый светильник добавляется на свободный участок активного трека. На плане его можно протащить через соседние приборы и перенести на другой участок этого же трека. На занятое место он не встанет. Переноса между разными треками пока нет.

Delete и Backspace удаляют выбранный элемент плана. При удалении трека удаляются и его светильники. Во время ввода текста и при открытом каталоге эта команда не срабатывает. Клик по пустому месту снимает выбор.

В каталоге по шесть товаров на странице. Поиск виден всегда, фильтры — если категорий несколько. После добавления светильника окно остаётся открытым, чтобы можно было добавить ещё несколько. При нехватке места карточка становится недоступной.

## Сохранение

Текущий формат — `schemaVersion: 2`. Проект хранится в localStorage под ключом `lights-prototype-v1`; его можно выгрузить в JSON и загрузить обратно. Старый формат с одним треком преобразуется при открытии. Файлы с более новой версией не принимаются.

Импорт исправляет некорректные размеры, ID и расположение. Если светильники из файла не помещаются, часть может быть удалена. Это поведение относится к импорту; при редактировании в интерфейсе изменение, для которого не хватает места, отменяется.

## Ограничения и производительность

Цена запрашивается через 200 мс после последнего изменения состава или размеров. Пока ответ не пришёл, на экране остаётся предыдущая цена, а скачивание спецификации недоступно. Устаревшие запросы отменяются. Перемещение внутри участка, смена цвета и поворот камеры не требуют нового расчёта.

Поиск, фильтры и страницы работают через API, но при старте клиент всё ещё загружает полный каталог через `/api/catalog`. Это нужно для геометрии и восстановления проекта. Проверки используют каталог из 123 светильников и 32 профилей. Для каталога существенно большего размера придётся загружать детали выбранных товаров отдельно.

В 3D объекты хранятся по трекам. При перемещении обновляются координаты; при добавлении светильника пересобирается его трек. Одновременно светят не больше четырёх источников, у остальных видны линзы. Потолок виден снизу и не закрывает обзор сверху.

Пределы проекта: 24 трека, 200 светильников, комната до 12 × 12 м. Эти числа заданы в прототипе и не описывают ограничения реального оборудования.
