# API

По умолчанию сервер слушает `http://localhost:8787`. Порт можно изменить через `API_PORT`. В режиме разработки Vite перенаправляет запросы `/api` на сервер.

Ответы приходят в JSON с заголовком `cache-control: no-store`. Типы описаны в `domain/types.ts`.

## Маршруты

| Метод | Путь                | Что возвращает                                          |
| ----- | ------------------- | ------------------------------------------------------- |
| GET   | `/api/health`       | `{ "ok": true }`                                        |
| GET   | `/api/catalog`      | Весь каталог: товары, формы, комплектующие, флаг `demo` |
| GET   | `/api/layouts`      | Формы треков с параметрами и участками                  |
| GET   | `/api/tracks`       | Страницу профилей треков                                |
| GET   | `/api/tracks/:id`   | Один профиль                                            |
| GET   | `/api/fixtures`     | Страницу светильников                                   |
| GET   | `/api/fixtures/:id` | Один светильник                                         |
| POST  | `/api/quote`        | Комплектацию и стоимость проекта                        |

ID в адресе нужно кодировать через `encodeURIComponent`.

Ошибки имеют вид `{ "error": "описание" }`:

- `400` — неверные параметры, JSON или URL;
- `404` — товар или маршрут не найден;
- `413` — тело запроса расчёта больше 64 КБ.

## Поиск

У `/api/tracks` и `/api/fixtures` одинаковые параметры:

| Параметр   | Значение                                                                              |
| ---------- | ------------------------------------------------------------------------------------- |
| `q`        | Часть названия, ID или описания; до 200 символов                                      |
| `category` | Для треков — `surface` или `recessed`; для светильников — значение `type` из каталога |
| `page`     | Номер страницы от 1 до 1 000 000; по умолчанию 1                                      |
| `pageSize` | От 1 до 50; по умолчанию 6                                                            |
| `sort`     | `name` (по умолчанию), `price-asc` или `price-desc`                                   |

```bash
curl 'http://localhost:8787/api/fixtures?q=48&page=1&pageSize=6&sort=price-asc'
```

Ответ содержит `items`, `total`, `page`, `pageSize` и `pages`. Если запрошенной страницы нет, сервер вернёт последнюю. Если ничего не найдено, `items` будет пустым, `total` — 0, а `pages` — 1.

## Расчёт комплектации

Пример для углового трека с двумя светильниками:

```bash
curl 'http://localhost:8787/api/quote' \
  -H 'Content-Type: application/json' \
  --data '{
    "tracks": [{
      "id": 1,
      "productId": "surface",
      "layoutId": "corner",
      "length": 2.5,
      "depth": 1.8,
      "fixtures": [
        { "type": "spot", "segmentId": "main" },
        { "type": "line", "segmentId": "side" }
      ]
    }]
  }'
```

`productId` выбирает профиль, `layoutId` — форму. Размеры берутся из `layout.parameters`: для угла нужны `length` и `depth`, для Z-формы ещё и `tail`. Значение `length` в запросе — один из размеров формы. Общую длину сервер считает по участкам.

Каждый светильник содержит ID модели в `type` и ID участка в `segmentId`. Для старых запросов без `layoutId` и `segmentId` используются `line` и `main`.

Координаты, цвет и яркость предпросмотра на цену не влияют. Сервер берёт цены из своего каталога, проверяет размеры, совместимость формы с профилем и вместимость участков. Лимиты — 24 трека и 200 светильников.

В ответе:

- `items` — общий список товаров: вид (`kind`), ID, название, описание, количество, цена за единицу и сумма;
- `tracks` — расчёт по каждому треку: `id`, общая длина `length` и комплектующие `requirements`;
- `total` — итоговая цена;
- `watts`, `lumens` — суммарная мощность и световой поток;
- `trackCount`, `fixtureCount` — количество треков и светильников;
- `demo` — используются ли тестовые данные.

## Источник данных

Сейчас каталог лежит в `domain/demoCatalog.ts`. Базы данных и редактирования товаров через API нет. Функция `createHandler(catalog, dist)` принимает каталог аргументом; так тесты подставляют свои товары.

Для реального каталога нужно подключить его загрузку и обновление цен. ID товаров должны оставаться стабильными, чтобы сохранённые проекты продолжали открываться.

На GitHub Pages API не запускается. Там используется локальный каталог и та же функция расчёта. Для актуальных цен в опубликованной версии понадобится отдельный сервер и настройка адреса API или прокси.
