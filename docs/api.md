# REST API

Сервер запускается на `http://localhost:8787`; `API_PORT` меняет порт. В разработке браузер обращается к `/api` через Vite proxy. Все ответы API — JSON с `cache-control: no-store`.

## Маршруты

| Метод | Путь                | Ответ                                                                          |
| ----- | ------------------- | ------------------------------------------------------------------------------ |
| GET   | `/api/health`       | `{ "ok": true }`                                                               |
| GET   | `/api/catalog`      | Снимок `Catalog`: товары, формы, аксессуары и флаг `demo`                      |
| GET   | `/api/layouts`      | Формы, параметры и определения участков                                        |
| GET   | `/api/tracks`       | Страница профилей треков                                                       |
| GET   | `/api/tracks/:id`   | Один профиль                                                                   |
| GET   | `/api/fixtures`     | Страница светильников                                                          |
| GET   | `/api/fixtures/:id` | Один светильник                                                                |
| POST  | `/api/quote`        | Итоговая спецификация, разбивка комплектующих по трекам, цена и характеристики |

ID в URL нужно кодировать через `encodeURIComponent`. Неизвестный товар или маршрут возвращает 404. Невалидный запрос — 400 с `{ "error": "описание" }`. Тело запроса расчёта ограничено 64 КБ; превышение — 413.

## Поиск и страницы

Параметры `/api/tracks` и `/api/fixtures`:

| Параметр   | Значения                                                                               |
| ---------- | -------------------------------------------------------------------------------------- |
| `q`        | Подстрока в названии, ID или описании, до 200 символов                                 |
| `category` | Для треков `surface` / `recessed`; для светильников точное значение `type` из каталога |
| `page`     | Положительное целое, по умолчанию 1                                                    |
| `pageSize` | 1–50, по умолчанию 6                                                                   |
| `sort`     | `name` (по умолчанию), `price-asc`, `price-desc`                                       |

```bash
curl 'http://localhost:8787/api/fixtures?q=48&page=1&pageSize=6&sort=price-asc'
```

Ответ: `{ "items": [...], "total": 3, "page": 1, "pageSize": 6, "pages": 1 }`. Страница за пределами результата прижимается к последней. При пустой выдаче возвращается пустой `items`, `total: 0`, `pages: 1`.

## Расчёт проекта

```bash
curl 'http://localhost:8787/api/quote' \
  -H 'Content-Type: application/json' \
  --data '{"tracks":[{"id":1,"productId":"surface","layoutId":"corner","length":2.5,"depth":1.8,"tail":2,"fixtures":[{"type":"spot","segmentId":"main"},{"type":"line","segmentId":"side"}]}]}'
```

`productId` — профиль, `layoutId` — форма. Набор обязательных размеров определяется `layout.parameters`. `length` — основной размер, не сумма длин фигуры. `fixtures` содержит ID моделей и участков. Если `layoutId` / `segmentId` отсутствуют, для совместимости используются `line` / `main`. Положение приборов внутри участка, координаты комнаты и цвет не влияют на демонстрационную цену и в запрос расчёта не входят.

Сервер проверяет товары, допустимую форму профиля, размеры, существование участков, суммарную вместимость каждого участка, пределы 24 трека / 200 светильников. Геометрию и обязательные комплектующие он вычисляет сам. Цена из тела клиента не используется.

Ответ `Quote` содержит:

- `items` — агрегированные товары с `kind`, `id`, названием, количеством, ценой за единицу и суммой;
- `tracks` — `{ id, length, requirements }` для каждого трека; здесь `length` уже **общая длина**;
- `total`, `watts`, `lumens`, `trackCount`, `fixtureCount`, `demo`.

## Подключение реальных данных

Контракты описаны в `domain/types.ts`. `createHandler(catalog, dist)` принимает каталог как зависимость; тесты подставляют большой каталог без изменения сервера. Сейчас источник — `domain/demoCatalog.ts`, постоянной БД и административных операций нет. Для товарной системы нужен адаптер чтения и обновления каталога/цен, стабильные ID, правила комплектации производителя и политика актуальности расчёта.

GitHub Pages не исполняет Node-сервер. Сборка `VITE_PAGES_DEMO=true` использует локальные данные и тот же доменный расчёт. Для динамических цен в опубликованном приложении потребуется отдельный сервер API и настройка адреса/прокси.

Некорректный URL запроса возвращает HTTP 400 с JSON-ошибкой; процесс сервера продолжает обслуживать последующие запросы.
